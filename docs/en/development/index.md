# Development

## Requirements

- Rust (stable toolchain) and Cargo
- Node.js + pnpm (frontend / desktop)
- WebView2 for the Windows build (usually present on Windows 10/11)

## Common commands

```powershell
# Rust (repository root)
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test
cargo run -p sbsave-cli -- --version

# Frontend / desktop (apps/desktop)
pnpm install
pnpm dev            # frontend only
pnpm build          # vue-tsc --noEmit + vite build
pnpm test           # vitest: locale key parity and interpolation
pnpm tauri dev      # desktop app development
pnpm tauri build    # Windows installers (NSIS + MSI)
```

## Project structure

```text
crates/sbsave-core/    # Rust core: GVAS/EVAS parsing, save extraction, catalog, diff analysis, report rendering
crates/sbsave-cli/     # clap CLI (binary sbsave); commands and output follow the original Python conventions
crates/sbsave-tools/   # Build-time data pipeline (binary sbsave-tools): catalog build / mine-names
apps/desktop/          # Tauri 2 desktop app: Vue 3 + Vite + TS + Tailwind CSS v4 frontend (project root)
apps/desktop/src-tauri # Tauri shell: list_saves / save_sources / inspect_save / open_save_dir / analyze_save / export_report / guide_links / list_browsers
data/raw/              # Committed data snapshots (including the hand-maintained crosswalk.json); never goes online at runtime
data/catalog.json      # Catalog generated by sbsave-tools catalog build; do not edit by hand
```

Module layout of `crates/sbsave-core`: `gvas` (GVAS/EVAS parsing), `savegame` (save discovery and
extraction), `catalog`, `analyze` (diff and NG+/DLC logic), `report` (JSON contract, Markdown,
console output) and `i18n` (localized UI messages). The desktop app's own structure and commands are
documented in
[apps/desktop/README.md](https://github.com/perillaroc/sblade-explorer/blob/main/apps/desktop/README.md).

## Data pipeline

```powershell
# Regenerate data/catalog.json
cargo run -p sbsave-tools -- catalog build
cargo run -p sbsave-cli -- catalog check

# Integration test: generated output is compared byte for byte with the committed file
cargo test -p sbsave-tools
```

After changing catalog data sources run `catalog build` first, then `catalog check`. Manual alias
mappings live in `data/raw/crosswalk.json` (single source of truth); guide text translations live in
`data/raw/api/i18n/`.

Refreshing the game name mapping (requires the game installed locally plus `cue4parse.exe`/`repak.exe`,
see `data/raw/README.md`):

```powershell
cargo run -p sbsave-tools -- mine-names `
  --game "H:\SteamLibrary\steamapps\common\StellarBlade" `
  --tools path\to\tools
```

## Tests and acceptance

- Tests use synthetic saves constructed byte by byte; real saves are never modified.
- The GVAS parser stays read-only and defensive: structs/arrays/maps/sets it cannot parse fall back to
  `RawValue`, and the reader always resynchronizes to `tag_start + size`.
- Migration acceptance (2026-09-14): node-for-node identical to the original Python `report --json`
  and character-for-character identical after Markdown normalization; the Python reference
  implementation was removed on 2026-09-15 and its history is preserved in the repo git
  (commit `33cb981`).
- Catalog regression sentinels are in [data.md](../reference/data.md#regression-sentinels).

## Testing tips

To verify the desktop app's "no save found" screen (when a save exists locally): `SBSAVE_SAVE_DIRS`
(semicolon separated) **replaces** the default save discovery directories for both the desktop app and
the CLI:

```powershell
$env:SBSAVE_SAVE_DIRS = "$env:TEMP\sbsave-empty"   # existing / missing directory exercise both messages
cd apps/desktop
pnpm tauri dev
```

The variable is for local testing only. The app remembers the last selected save, so use
**Switch to automatic** or **Reset to defaults** in the settings before testing the empty state.

## Documentation site

The online documentation is a VitePress site (`docs/`, Chinese by default, English under `docs/en/`):

```powershell
cd docs
pnpm dev        # local preview (http://localhost:5173 by default)
pnpm build      # build; dead links fail (the same command as CI and Netlify)
```

New or changed pages must be kept in sync across both languages: after editing a Chinese page,
update the matching file under `docs/en/` and use the English UI terms from
`apps/desktop/src/locales/en.ts`; internal links in English pages use `/en/...` or relative paths.
Locale switching, navigation, sidebar and footer are configured through the top-level
`locales[...].themeConfig` in `docs/.vitepress/config.ts`. `documentation-inventory.md` is an
internal document (`srcExclude`): it is neither published nor translated.

## CI and releases

Two GitHub Actions workflows (`.github/workflows/`):

| Workflow | Trigger | Content |
| --- | --- | --- |
| `ci.yml` | push `main` / PR / manual | Rust job (**windows-latest**): `cargo fmt --all --check`, `clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, CLI smoke test; frontend job (ubuntu): `pnpm install --frozen-lockfile` + `pnpm build` + `pnpm test`; docs job (ubuntu, `docs/`): `pnpm install --frozen-lockfile` + `pnpm build`, which builds the VitePress site (dead links fail the build); deployment is handled by Netlify |
| `release.yml` | push tag `v*` / manual | First runs the full `ci.yml` gate, then checks that the tag matches the version in `tauri.conf.json`, builds the portable desktop zip and the CLI zip, and creates a **draft** Release with `gh release create`; publish after manual review |

Release procedure:

```powershell
cd apps/desktop
pnpm bump 0.2.0        # syncs tauri.conf.json / package.json / Cargo.toml and refreshes Cargo.lock
cd ..\..
git commit -am ":bookmark: 发布 v0.2.0"
git tag v0.2.0
git push origin main v0.2.0
```

> Releases use lightweight tags (consistent with `v0.1.0` and `v0.2.0`): `git push --follow-tags` does
> not push lightweight tags, so the tag must be given explicitly.
> Only annotated tags (`git tag -a v0.2.0 -m ":bookmark: 发布 v0.2.0"`) can use `--follow-tags`.

`release.yml` verifies that the tag matches the version in `tauri.conf.json` and fails otherwise.

Versions follow SemVer: `pnpm bump` accepts `x.y.z` and `x.y.z-prerelease` (such as `1.0.0-rc.1` for
test builds) but not build metadata (`+...`); the prerelease flow is identical, just tag
`v1.0.0-rc.1`.

> The Rust job must run on Windows: the `sbsave-tools` integration test compares
> `data/catalog.json` byte for byte and generation uses platform newlines (Windows CRLF).
> `.gitattributes` pins that file to CRLF.

## Layout invariants

Read this before changing the directory layout:

- `crates/` must stay directly under the repository root (`sbsave-tools::repo_root()` walks up two
  levels);
- `data/catalog.json` must stay three levels above `crates/sbsave-core` (embedded at compile time with
  `include_str!`);
- `apps/desktop/src-tauri` must be listed in the workspace `members` (tauri-action resolves the
  workspace `target/` through it).
