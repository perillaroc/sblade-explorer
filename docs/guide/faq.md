# 常见问题

## 会修改我的存档吗？

不会。程序只读取存档，解析和统计全部在内存中完成，绝不会写入存档文件。
本地设置也仅保存在本机，不会写入存档或注册表。

## 需要联网吗？

不需要。所需数据均内置于程序，运行时不会联网。
只有点击「图文攻略」「视频攻略」或搜索攻略按钮时，才会通过系统浏览器打开相应链接。

## 支持哪些平台？

目前支持 Windows 10/11。自动查找存档仅覆盖[存档位置](./save-location.md)中列出的 Windows 路径，不支持其他操作系统。

## 需要安装吗？如何升级？

不需要。便携版解压后即可使用，不会创建开始菜单快捷方式或卸载项，也不会写入注册表。
升级时，用新版 `sblade-explorer.exe` 替换旧文件即可。

## 提示缺少 WebView2 运行时怎么办？

请安装 Microsoft Edge WebView2 Evergreen Runtime，然后重新启动程序。
Windows 10/11 通常已随 Edge 安装该组件。

## 找不到存档怎么办？

界面会列出实际扫描的目录，已存在的目录可以点击「打开」在文件资源管理器中查看。
也可以点击「选择存档文件…」，直接选择任意位置的 `StellarBladeSave*.sav`。
扫描目录和文件名规则详见[存档位置](./save-location.md)。

## 为什么图鉴不计入收集进度？

目录进度只统计 13 类收集品。孽奇拔和角色图鉴根据成就别名 `Ach_Album_Unlock_*` 判断是否解锁，
在报告和界面中单独显示，因此不计入目录进度。

## 条目显示「映射待确认」是什么意思？

表示该条目的名称与别名映射置信度较低。目录库目前**没有**低置信度条目：埃多斯9号 6 座营地已通过
存档 `DataMap_SBEnv` 的坐标与数据表 `CoinSpawnPointName` 邻近匹配确认行号。如果使用旧版目录库或
自定义目录库时仍看到该标记，表示对应条目尚未确认；这不影响已获得状态的判定。
如需修正，可以使用自定义目录库，详见[数据来源与目录库](../reference/data.md#自定义目录库)。

## 如何修正缺失或错误的条目？

创建用户覆盖文件 `%LOCALAPPDATA%\sbsave\catalog.user.json`，或使用 CLI 的
`--catalog <路径>` 临时加载覆盖文件，无需重新生成目录库。文件格式见
[自定义目录库](../reference/data.md#自定义目录库)。

## 游戏更新后解析失败怎么办？

解析失败时，程序会显示明确的错误信息。请确认游戏版本与存档版本是否匹配，
不要强行使用旧版本目录库解析新版本存档。

## 支持 NG+ 和 DLC 内容吗？

支持。程序读取存档中的 `NewGamePlusPlayCount`，标注「需要二周目(NG+)」或「需要三周目(NG++)」。
DLC 和特典物品会单独标记，也可以在周目矩阵的「DLC/特典」列中对照查看，
详见[周目与收集矩阵](./collections.md#周目与收集矩阵)。
存档没有可靠的 DLC 授权字段，因此需要在设置中声明已拥有的 DLC，见下一条。

## 为什么 DLC 条目不再显示「限定」？

请在「设置 → 已拥有的 DLC」中勾选尼尔 / NIKKE，或使用 CLI 的 `--dlc nier,nikke`。
声明拥有后，对应条目不再按 DLC 限定阻塞，而是显示「已拥有，尚未获得」，并进入「可优先收集」；
未声明的 DLC 仍会显示为限定。该设置只保存在本机，不会写入存档。

## 为什么有的条目显示「已错过」，有的显示「还来得及」？

程序会读取存档中的任务状态，结合目录库中的易错过规则判断：

- 「已错过」：本存档已经越过不可返回节点，或奖励所对应的支线/布告栏委托已出现在失败列表；
- 「还来得及」：当前仍可获得，建议离开前收集；
- 「可错过(注意节点)」：没有任务规则、旧存档没有任务数据或条件不足，程序无法判断；
  这种情况下不会武断标记为已错过。

需要更高周目或未拥有的 DLC 条目会先按对应限制显示。规则与 JSON 字段见
[存档解析与判定](../reference/data.md#存档解析与判定)。

## 分类页底部为什么会提示有未关联到目录条目的已获得别名？

表示存档中有一些已获得别名无法匹配到目录库条目，可用于了解数据覆盖情况。
如需修正映射，见[自定义目录库](../reference/data.md#自定义目录库)。

## 支持装备词条（Gear）和技能（PT）吗？

装备词条（Gear）已支持：77 件可拾取的装备列在「成长」区块，不计入收集进度。攻略标题末尾的 ★ 数对应稀有度
（★ 普通、★★ 精良、★★★ 稀有），升级后的 Mk2 同属一件装备，不会重复计数。技能（PT）仍未支持。

## 辅助脊椎（Exospine）算收集品吗？

不算。12 条辅助脊椎列在「成长」区块，不计入收集进度；获得状态读取存档的辅助脊椎强化记录，
升级后的 Mk2 同属一件，不会重复计数。

## 为什么装备和辅助脊椎不计入收集率？

收集率只统计 13 类收集品（808 条）。装备与辅助脊椎属于成长系统，单独列在「成长」区块，
这样既能看到它们的状态，又不会改变既有的目录进度口径；它们也不需要全部收集才能推进游戏。

## 为什么没有机体核心 / Beta 核心 / 武器核心 / Tumbler 模块 / 无人机模块的进度？

这些是消耗品：存档只保留当前背包库存（且受商店购买和多周目继承影响），没有逐件拾取记录；
无人机与 Tumbler 的攻略条目又都是同名条目，无法对应到具体拾取点。因此不展示它们的收集进度，
避免给出误导性的「已获得 / 总数」。装备词条和辅助脊椎有可靠的逐项状态，已在「成长」区块提供。

## 为什么补给箱 / 高级补给箱没有进度？

攻略里的 193 个补给箱和高级补给箱是通用容器，内容是消耗品或随机物资，不进入物品清单。
存档用 `ChangeState_ZoneEnv_*_SupplyBox` 成就记录开启状态（本机 287 条、100% 参考存档 293 条），
但攻略条目只有区域和地点描述、没有容器别名，两个数量也无法一一对应，因此不展示逐项进度。

## 设置保存在哪里？

侧栏底部「设置」中的外观（暗色 / 浅色 / 跟随系统）、默认搜索引擎（必应 / 百度 / 谷歌）、
打开链接的浏览器、启动时打开的存档以及已拥有的 DLC 等偏好仅保存在本机。
攻略链接会在所选浏览器中打开；如果无法启动该浏览器，则自动改用系统默认浏览器。

## 如何使用 CLI？

参见 [CLI 文档](../cli/index.md)：`saves` 用于列出存档，`report` 用于分析并导出报告，
`dump` 用于调试，`catalog` 用于校验目录库。
